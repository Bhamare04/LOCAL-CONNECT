# Place data collection guide

This guide prepares `places.csv` for reliable, traceable data collection. It does not supply, infer, or change factual values. Retain the existing `place_id` values and all 50 places.

For every collected factual value, record the source and the verification date. A future schema revision should add `source_url` and `last_verified_at` columns; do **not** add them to `places.csv` until that revision is explicitly approved.

## Reliable source guidance

| Field | Recommended source type and collection rule |
| --- | --- |
| `entry_fee` | Official tourism site or official attraction website. Record the exact current published fee; retain an empty value if none can be verified. |
| `average_rating` | One clearly identified, consistent public source across the dataset, such as Google Maps. Record the displayed numeric value and source URL. |
| `rating_count` | The same source used for `average_rating`, collected on the same verification date. |
| `estimated_visit_hours` | Official tourism information or another documented reasonable source. Record the source and distinguish suggested visit duration from opening hours. |
| `rain_suitability` | Carefully derive from documented place characteristics and documented weather/travel information; retain `Unknown` if evidence is insufficient. |
| `heat_suitability` | Carefully derive from documented place characteristics and documented weather/travel information; retain `Unknown` if evidence is insufficient. |
| `best_season` | Official tourism information or reliable travel information. Preserve `Unknown` where a dependable source is not available. |

## Controlled values

Use only these values when evidence supports a classification:

`rain_suitability`

- `Low`
- `Medium`
- `High`
- `Unknown`

`heat_suitability`

- `Low`
- `Medium`
- `High`
- `Unknown`

`best_season`

- `Winter`
- `Summer`
- `Monsoon`
- `All Year`
- `Unknown`

## Ready for next step

ML training can begin only when all of the following are true:

- no unexplained missing numeric values
- reliable source for factual values
- consistent categorical values
- documented treatment of `Unknown` values
- documented training-label strategy
## Real Geoapify dataset collection

`ml/scripts/collect_places_dataset.py` collects the first real place dataset for the ten target cities:
Mumbai, Jaipur, Surat, Nashik, Vadodara, Bangalore, New Delhi, Chennai, Hyderabad, and Kolkata.

The collector calls the existing Node Geoapify service functions in
`server/services/travelService.js` through
`server/services/datasetCollectionBridge.js`. It then applies the existing
`processPlaces()` filtering and duplicate-removal logic from
`server/services/placeProcessor.js`. It does not use Google Places, train a
model, or alter the application endpoints.

Run it from the repository root:

```text
python ml/scripts/collect_places_dataset.py
```

The output is `ml/data/places_real.csv`. Geoapify place IDs, names, categories,
coordinates, and target city labels are collected from the provider. Geoapify
does not reliably provide indoor/outdoor classification or weather suitability
labels in this collection step, so those columns use the explicitly documented
value `Unknown`. Missing provider values remain blank; no ratings, prices,
durations, or weather labels are fabricated. If Geoapify omits a `place_id`,
the `place_id` cell remains blank and the row is retained without inventing an
identifier.
